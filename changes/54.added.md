The demo has a master–detail example: a **payment batch** (`PAY-0001`) whose sub-process step starts one **payment** child (`PAY-0001/3`) per payment and whose `settle` stage waits until none is active, failing the batch if any payment failed. The simulation page pays the next batch, optionally with one payment failing to post; paying again retries the failed payment and settles the same batch. The batch's instance page lists its payments as children, each linking back up, and `Detail` says what each is about. Payments debit the demo accounts, so the next end of day shows the lower balances.
